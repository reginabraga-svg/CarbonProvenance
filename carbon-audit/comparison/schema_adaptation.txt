The first ProvSQL run used a primary key on the business key. UPDATE provenance preserves a prior row and represents the new row separately, and the tested WASM build rejected updates with a duplicate-key violation. The source declaration adapter already checks input key uniqueness. The physical primary key was therefore removed from facts for BOTH the SQL reference and ProvSQL comparators. Active-world key uniqueness remains checked by each source snapshot and by the one-row-per-output assertion. This adaptation is recorded, not interpreted as lack of update provenance support. provsql_initial_pk_results.json preserves the first execution. The frozen protocol expectations and source values were not changed.
